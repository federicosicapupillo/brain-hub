## PART A — Auto-verificabile

### A0. Severity Classification

- **Severity:** S3 (operator-facing dashboard backed by gated read endpoint).
- **Blast radius:** read-only aggregator + four write paths that all reuse the four already-approved endpoints (`/api/execute-internal-action`, `/api/execute-external-action`, `/api/rollback-internal-action`, `/api/recover-orphan-execute-gate`). The Console never introduces a new mutation route.
- **Honest State Pattern applied:** every source (`execute_receipts`, `internal_execute_artifacts`, `execute_idempotency`) has an isolated wrapper (`safeQuery`) and is rendered with its own `live | empty | error` badge; one broken source cannot collapse the page.

### A1. Funzionalità

Tutto verificato sul dev server live (`http://localhost:8080/execute-console`) con sessione Supabase reale.

- `GET /api/execute-console-data` — gated da `evaluateAction({ action: "read_execute_console_data", entity: { type: "user", id: auth.uid() } })`. Risposta osservata: `engine_status` + 9 `available_actions` + 3 `blocked_actions` + 36 receipts + 20 artifacts + 29 idempotency rows + 7 orphan_states, `total_ms = 107`.
- Tabs renderizzati e cliccabili via Playwright (`get_by_role("tab", …)`):
  - **Available actions (9)** — 8 internal MEDIUM + 1 external LOW (`external_webhook_test_ping`). Detail panel mostra risk, scope, requires_confirmation, supports_dry_run/live/rollback.
  - **Blocked (3)** — `high_live_actions` (high_live_blocked), `external_medium_connector` (medium_external_connector_not_implemented), `create_snapshot` (rollback_not_supported).
  - **Receipts (36)** — lista con outcome_kind, risk badge, idempotency preview, manual_review flag, safe_error_message.
  - **Artifacts (20)** — etichettato in UI come **"Execute artifacts"** (non "Internal artifacts"), badge `execute_scope` `internal|external` derivato da `payload.execute_scope`, payload preview redacted.
  - **Orphan / Manual review (7 + 6)** — vedi §Test G.
  - **Rollback** — filtra solo artifact internal + `rollback_available=true` + non già rolled back.
- Dialog "Confirm" per `external_live`, `rollback`, `recover` mostra cosa succederà / cosa NON succederà (testi italiani, no side-effect impliciti).

### A2. Governance & RBAC

- Nuovo permesso `read_execute_console_data` aggiunto su entity `user` in `src/lib/governance/rbacModel.ts:53-65`. Nessun nuovo permesso write.
- Endpoint `src/routes/api/execute-console-data.ts`:
  - Senza bearer → `401 { error: "unauthorized", reason: "no_session" }` (verificato).
  - Token valido ma governance fail → `403 { error: "forbidden", reason, audit_record }`.
  - `owner_id` è SEMPRE derivato da `supabase.auth.getUser().user.id` (user-scoped client con bearer); body input NON contiene mai `owner_id`. Cross-user leak impossibile per costruzione.
- I quattro endpoint write rimangono governati dai loro RBAC originari (`execute_internal_action`, `execute_external_action`, `recover_orphan_execute_gate`). La Console NON aggiunge bypass.
- Redaction server-side in `execute-console-data.server.ts:36-88`: rimuove `Bearer …`, `sk-…`, `eyJ…` JWT, email, e svuota chiavi `authorization|token|secret|api_key|password|access_token|refresh_token` ricorsivamente fino a depth 4.

### A3. Stato dei dati

- Tabelle lette: `execute_receipts`, `internal_execute_artifacts`, `execute_idempotency` (tutte già esistenti da v3.35a/b/c). Nessuna nuova migrazione.
- Per-source meta (`live | empty | error`) sempre presente nella risposta, anche su failure. Esempio reale:
  ```
  receipts: live, 36, 93ms
  artifacts: live, 20, 101ms
  idempotency: live, 29, 88ms
  total 107ms
  ```
- `gate_age_ms` calcolato lato server da `Date.parse(created_at)`; orphan TTL letto da `getOrphanGateTtlMs()` (single source of truth con il reaper).

### A4. Performance & Resilienza

- Tre query SELECT user-scoped in parallelo (`Promise.all`), limiti 50/50/100. Totale osservato 107ms sul dev server con 36+20+29 righe.
- `safeQuery` cattura sia `error` PostgREST sia eccezioni JS; degrade graceful — un source rotto produce `status:"error"` + safe message ma non blocca gli altri.
- Frontend usa React Query con `staleTime: 15s` e `refetchInterval: 30s`. Nessun polling aggressivo.
- Nessuna chiamata sincrona a dispatcher dal componente; tutte le mutazioni passano per `fetch` a uno dei quattro endpoint approvati.

### A5. Type Safety

- `npx tsgo --noEmit` → 0 errori sul nuovo codice (output filtrato per `execute-console` vuoto, full output vuoto).
- Nessuna `any` introdotta nel surface UI; uso di `unknown` + narrowing per payload preview.

### A6. Limiti residui (dichiarati, non ipotetici)

- **Browser test runner:** NON presente nel repo. Nessun Playwright/Cypress configurato come dipendenza npm. La verifica visiva di questa patch è stata fatta con Playwright pre-installato nel sandbox di build, NON con un runner committato. → debito esplicito: aggiungere `@playwright/test` + uno smoke test del `/execute-console` in v3.36+.
- **Sidebar:** voce "Execute Console" aggiunta a mano in `src/components/AppSidebar.tsx:73` dentro l'array `items` statico. NON esiste un registry centralizzato che mappa OS modules → sidebar entries. → debito esplicito (già noto da v3.28): registry-driven sidebar.
- **Artifact table condivisa:** la tabella `internal_execute_artifacts` ospita anche le scritture external (con `payload.execute_scope = "external"`). In UI è etichettata "Execute artifacts" con badge `execute_scope` per ogni riga, NON "Internal artifacts". Il nome fisico della tabella resta misleading → debito noto da v3.35b, non risolto qui.
- **Idempotency key preview:** in UI mostriamo `prefix(8)…suffix(4)`. Il backend di recover accetta solo la chiave intera; la Console invia la chiave NON troncata letta dalla risposta API server (mai dal DOM). Nessun client mutation costruisce chiavi.
- **Rollback su external:** non supportato (registry lo dichiara). UI nasconde correttamente artifact external dal tab Rollback.
- **HIGH live + MEDIUM external connector:** sempre blocked, mostrati nel pannello Blocked con `reason_kind` esplicito. Nessun toggle per abilitarli — coerente con runtime-risk-model v1.1.

### A7. Debito tecnico introdotto

- Nessuno nuovo. Tutto il debito elencato in A6 era già presente prima di v3.35d; questa patch lo rende visibile in UI (es. badge `execute_scope`, pannello Blocked, sezione manual-review) invece di nasconderlo.
- Una unica leggera duplicazione: la classificazione `scopeFor(action_type)` ricostruisce lo scope ispezionando i due registry. Accettabile finché i registry restano single source of truth; se mai introducessimo un terzo scope (es. `mcp`) andrà rifattorizzato in un helper condiviso col dispatcher.

### A8. Debiti ereditati — stato esplicito

- v3.35a (Internal rollback policy): risolto solo per visualizzazione (badge `supports_rollback`). Niente nuove azioni rollbackable.
- v3.35b (External sandbox only): rispettato. UI mostra `Live execute` button SOLO se `scope === "external"` e `status === "available"`; per internal MEDIUM la Console rinvia al modulo originario ("Internal MEDIUM live execute requires a real payload built by the originating module").
- v3.35c (orphan gate manual review): risolto a livello UI — sezione dedicata, testo italiano obbligatorio, `auto_reexecuted=false` visibile per ogni riga (vedi Test G).
