## A0 — Patch identity

- **Patch ID:** v3.36
- **Title:** External MEDIUM Connector — `external_n8n_controlled_webhook`
- **Predecessors (must be passed):** v3.35a, v3.35a.1, v3.35b, v3.35c, v3.35d (all ✅)
- **Scope statement:** Introduce the first real MEDIUM-risk external connector to the Execute surface, routing exclusively to an allowlisted set of n8n workflows. Close the Principio 3 debt left open by v3.35d (`execute-console-data.server.ts` returning `{ ok, data }` instead of `ServiceOutcome<T>`).
- **Out of scope (explicit):** HIGH live actions, arbitrary URL webhooks, social publishing, email send, financial/health/legal data flows, GitHub mutations, payment connectors.
- **Action_type registered:** `external_n8n_controlled_webhook` (MEDIUM, requires confirmation, no rollback).
- **Workflows allowlisted (v3.36):** `brainhub_telegram_approval_preview`, `brainhub_n8n_controlled_echo_medium`.

| Dimension | Classification | Notes |
|---|---|---|

## A2 — Functionality verification

- ✅ `validateExternalPayload` accepts the new action-type fields (`workflow_key`, `title`, `metadata`) only when the registry entry declares `allowlisted_workflow_keys`; rejects them otherwise (`payload_field_not_allowed`). Hard-forbidden keys (`webhook_url`, `arbitrary_url`, `endpoint`, raw headers/body, attachment, file, html) are rejected before any other check.
- ✅ Dispatcher rejects unknown workflow keys with `workflow_not_allowlisted`. Rejects non-MEDIUM allowlisted workflows with `workflow_risk_not_medium` (defense in depth: even if a future entry were misclassified in the workflow registry, the dispatcher refuses to dispatch).
- ✅ Dry-run path returns local-only preview; never calls n8n unless `n8n_test_mode_available: true` (v3.36 ships no such workflow → always local). Documented intentional debt.
- ✅ Live-execute path calls `invokeN8nControlledWorkflow` (the new service), which returns `ServiceOutcome<N8nControlledConnectorResult>` — never throws.
- ✅ Endpoint URL is read **only** from the per-workflow `endpoint_env_var`. The client cannot supply a URL; the validator rejects any URL-like payload key.
- ✅ Response is size-bounded (`max_preview_bytes`) and redacted via `previewResponseText` + `redactObject` using `redaction_rules`.
- ✅ Receipt includes: `external_action_type`, `connector_name`, `handler_name`, `workflow_key`, `dry_run`, `live_execute`, `confirmation_id`, `confirmation_source`, `confirmed_at`, `request_hash`, `payload_preview_redacted`, `response_preview_redacted`, `http_status`, `timing_ms`, `service_outcome_status`, `rollback_supported: false`, `orphan_gate_reaper: "v3_35c_inherited"`.
- ✅ Artifact includes `workflow_key`.
- ✅ Execute Console UI reports `medium_external_connector_available` from a live check (registry enabled + env var present) and emits `medium_external_connector_env_missing` warning when the env var is absent.

**Manual verification limits:** Live n8n calls are not exercised from this sandbox. The connector is verified to PASS typecheck, route through validator/governance/idempotency, and to surface a `missing_env` ServiceOutcome when the env var is unset (the expected behavior in the current environment).

## A4 — Security & governance

- **Default-deny:** Action enabled in registry, but governance evaluator gates `execute_external_action` via RBAC (unchanged from v3.35b).
- **No client-supplied URL:** Hard-forbidden keys list updated (`webhook_url`, `arbitrary_url`, `endpoint`, `raw_headers`, `raw_body`, `attachment`, `file`, `html`).
- **Workflow registry server-only:** `n8n-controlled-workflows.ts` imported only by dispatcher and console data fetcher. No client bundle import.
- **Env var indirection:** Each workflow declares its own `endpoint_env_var`. The dispatcher refuses to invoke when the env var is missing (`endpoint_env_missing:<VAR>`).
- **Redaction:** Inbound payload preview redacted (`redactPayload`). Outbound response redacted via `previewResponseText` + per-workflow `redaction_rules`. Safe error messages truncated to 240 chars; `Bearer …` and email patterns scrubbed.
- **Idempotency gate-first (v3.35a.1):** unchanged, inherited.
- **Orphan Gate Reaper (v3.35c):** unchanged, inherited. Receipt records `orphan_gate_reaper: "v3_35c_inherited"` (was `not_implemented_v3_35b_debt_v3_35c` in v3.35b receipts).

## A7 — Technical debt declared

1. **`brainhub_n8n_controlled_echo_medium` is shipped enabled.** Justification: in environments without a reachable Telegram Approval Layer, the operator needs a way to exercise the connector end-to-end. The workflow is `echo_safe` (`side_effect_profile`), MEDIUM by classification, and explicitly allowlisted. **Recommended removal trigger:** once the Telegram Approval Layer is verified reachable in all target environments, disable `brainhub_n8n_controlled_echo_medium` (`enabled: false`) and remove from the allowlist in the patch after v3.36.
2. **No real n8n call exercised from this sandbox.** Typecheck passes; runtime live-execute requires `BRAINHUB_N8N_CONTROLLED_WEBHOOK_URL` to be set in the deployment environment. The console correctly reports `medium_external_connector_status: "missing_env"` until then.
3. **Receipts table is shared between internal and external scopes.** Inherited from v3.35b. Not addressed in v3.36. Tracked separately.
4. **Dry-run is local-only for all v3.36 workflows.** None of the shipped workflows declares `n8n_test_mode_available: true`. When n8n test mode becomes available for a workflow, the dispatcher will need a small extension to forward dry-runs to the test endpoint.

### Test H — idempotency race (8 concurrent live executes)

Mock configured: HTTP 200, valid shape, 350 ms fixed delay, call counter
enabled. Same `idempotency_key` and `confirmation_id` across 8 parallel
POSTs to `/api/execute-external-action`. Expected and asserted by the
harness:

- `executed = 1`, `replayed = 7`
- distinct `receipt_id` set across the 8 responses: `1`
- `execute_receipts` rows for that key: `1`
- `execute_idempotency` rows for that key: `1`
- `internal_execute_artifacts` rows linked to that key: `1` *(queried via `payload->>'idempotency_key'`; the table has no dedicated column, see A7 debt)*
- mock endpoint calls: **`1`** (not 8) — confirms the gate-first scheme
  collapses the race before any outbound HTTP is issued.

DB-side counts are gathered via `psql` using the harness-host `PG*` env
vars. If `psql` is not on PATH the harness prints `db_counts: skipped_no_psql`
and only the API-level numbers are asserted.

### Redaction evidence

Each harness request carries fake secrets in `payload.message`:
`Bearer abc123`, `sk-test-secret-001`, `eyJhbGciOiJIUzI1NiJ9.fake.sig`,

## v3.36.1 Evidence Fix — Operator Closure

Patch chiusura gap evidenziati dal v3.36.1 Evidence Run. Nessuna feature
nuova; nessun avanzo verso v3.37; nessuna chiamata a n8n reale.

### Problemi individuati e fix applicati

1. **Redaction leakage** (FAIL → PASS)
   - Pattern hardenizzati in `src/lib/execute-dispatcher/external-validators.ts`
     (`redactString`), applicati **in ordine vincolante**:
     1. JWT generico `/eyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+/g`
        (header, body, log testuale — ovunque appaia serializzato).
     2. Querystring secrets `/([?&](?:token|key|secret|access_token)=)[^&\s"']+/gi`
        → `$1[REDACTED]`.
     3. Bearer tokens.
     4. `sk-…` style keys.
     5. Email address.
   - Motivo dell'ordine: un JWT in `?token=…` resta coperto comunque dalla
     querystring redaction; un JWT fuori querystring (header `Authorization`,
     body JSON, log) sarebbe stato perso se la querystring fosse partita prima.
   - `safe()` nel dispatcher external ora delega a `redactString` invece di
     usare regex parziali, eliminando la fonte storica di leak.
   - `auditRecord.response_preview_redacted` viene ri-redatto a livello
     dispatcher (defence in depth oltre al preview del connector).
   - Coperti anche valori URL-encoded: `?token=abc%2Fdef%3Dghi`,
     `&access_token=eyJabc.def.ghi%2Fsig`, `&secret=value%2Bwith%2Fencoded%3Dchars`.
     La regex si ferma correttamente al separatore reale `&`, non a `%26` /
     `%2F` / `%3D` dentro il valore.

2. **`audit_record.error_kind = null` nei failure modes** (FAIL → PASS)
   - `HandlerResult` ora include `error_kind` obbligatorio + `mock_or_real`.
   - Mapping stabile e basso-cardinalità:
     - timeout → `n8n_timeout`
     - HTTP 4xx/5xx → `http_<status>` (es. `http_418`, `http_503`)
     - shape invalido → `invalid_response_shape`
     - fetch/network → `fetch_failed`
     - env mancante → `n8n_env_missing`
     - workflow non allowlisted → `workflow_not_allowlisted`
     - workflow non MEDIUM → `workflow_risk_not_medium`
   - `safe_error_message` riflette l'`error_kind` per i failure (e resta
     redatto via `redactString`).

3. **DB artifact/audit contract — VINCOLANTE** (inconclusive → PASS)
   - Niente nuova tabella. La fonte di verità è `internal_execute_artifacts`
     con `payload.artifact_type = 'external_medium_connector_dispatch'`.
   - Record contiene: `artifact_type`, `connector_type` (`n8n_controlled`),
     `idempotency_key`, `receipt_id`, `dispatch_status`, `service_outcome_status`,
     `mock_or_real`, `error_kind`, `request_hash`, `payload_preview_redacted`,
     `response_preview_redacted` (redatto), timing/http_status, `created_at`.
   - L'artifact è scritto pre-handler (gate-first, idempotent per chiave) e
     **stampato post-handler** con `dispatch_status` / `receipt_id` /
     `mock_or_real` / `error_kind`.

```

artifact_type = external_medium_connector_dispatch
```
